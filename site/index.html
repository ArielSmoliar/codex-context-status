02 / Continuity

A new chat.
A considered handoff.

Choose whether you’re continuing, planning a large step, or switching tasks. Use the guidance to decide what comes next.

The 80% and 90% checkpoints are advisory. They are not quality scores or known compaction thresholds.

  1. 1

    In the current chat

    Prepare, then review.

    Use the preparation prompt to capture the goal, decisions, work state, checks, and next action. Review the summary and correct it before moving on.

  2. 2

    In the new chat

    Reconcile, then resume.

    Paste the reviewed handoff into the resume prompt with your current request. The next chat is asked to check the workspace before continuing.

You control what moves between chats. Nothing transfers automatically.Read the handoff guide ↗

03 / What to expect

Useful signals.
Clear limits.

Recorded telemetry can inform a decision. It cannot tell the whole story of a session.

Is this an exact, live context meter?+

It estimates capacity using the last recorded request footprint and runtime-reported limit. Unreported work is excluded. Cumulative token consumption is different from the amount currently occupying context.

Does it read or upload my conversations?+

The local MCP server reads the exact selected session log and returns allowlisted telemetry. It does not return conversation content or modify logs. The inspector has no external network dependencies. Handoff prompts run only when you choose to submit them in Codex.

Will it tell me when model quality drops?+

No. The guidance uses recorded capacity and your intended next step. It does not diagnose quality degradation or guarantee that a fresh chat will improve results.

What happens if I switch models?+

A switch is detected when the new model appears in recorded turn metadata, typically after your next message. The old context limit is cleared and capacity waits for fresh usage. A model-picker click alone is not telemetry.

Will it work with my Codex setup?+

You need local Codex desktop with MCP Apps support, readable local telemetry, Node.js 20+, and Python 3.10+ with timezone data. Live verification currently covers one macOS desktop build, 26.1007.21159. Other releases and remote or ephemeral chats need their own evidence. See the compatibility record.

Terminal · Preview installation
git clone https://github.com/ArielSmoliar/codex-context-status.git codex-context-status-pilot-b19f0a0 &&
cd codex-context-status-pilot-b19f0a0 &&
git checkout --detach b19f0a01a18c126a2c69615eef3f4285c73b2c61 &&
python3 scripts/install.py

Then apply: python3 scripts/install.py --apply

Use a new checkout folder and stop if any command fails. Run the dependency and MCP registration commands printed by the helper. Preserve existing settings, restart Codex if needed, then invoke $context-status.

This is a pilot candidate, not a broadly validated release. Setup requires Git and the Codex CLI for MCP registration, plus the desktop, Node, and Python requirements above. Existing local edits or installation conflicts stop the helper.
